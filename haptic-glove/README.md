# 触觉手套：把游戏里的触感同步到现实

目标：手指在游戏里摸到东西（毛皮、石头、水、别人的手），手套上由许多小块（tactor）按不同状态组合，模拟“被抚摸”的感觉。

本目录包含**设计方案**和一个**可运行的渲染原型**（游戏接触事件 → 每个小块的状态 → 二进制帧）。硬件部分尚未制作，下面的参数都是起步值，需要实测调整。

> **重要更正**：本文 §2、§3 里“每指腹 12 个小块”和“LRA 频率 80–300 Hz 独立可调”**未经验证，且很可能不成立**（LRA 是窄带谐振器；指腹上的振动难以局部化）。请先读 [FEASIBILITY.md](FEASIBILITY.md)，其中有查证结果、修订方案和验证实验。

```
python3 demo_stroke.py        # 看一次抚摸在指腹 3x4 阵列上的幅度热图
python3 -m pytest -q tests    # 5 个测试
```

## 1. 系统结构

```
游戏引擎(Unity/Unreal)          主机侧渲染器                手套 MCU                执行器
指尖碰撞体 -> 接触事件  --->  glove/render.py   --1kHz-->  解帧+驱动  --->  小块阵列
{手指,接触点,法向力,        接触->每块状态             (BLE5 / 2.4G / USB)   (压力+振动)
 切向速度,材质}              press / amp / freq
        ^                                                       |
        └──────── 手指关节角(IMU/弯曲传感器) 回传，用于手部追踪 ─┘
```

- 游戏侧只发“物理事实”（哪根手指、接触点、力、滑动速度、材质），不关心硬件；换手套只换渲染器。
- 目标端到端延迟 < 20 ms（触觉对延迟比画面更敏感）。

## 2. 小块怎么布置

| 区域 | 阵列 | 间距 | 数量 |
|---|---|---|---|
| 5 个指腹 | 3 列 × 4 行 | 6 mm | 60 |
| 手掌 | 4 × 4 | 14 mm | 16 |
| 合计 | | | 76 |

指腹的两点分辨力约 2–3 mm，6 mm 间距做不到“每个点都分辨”，所以**不靠堆密度，靠算法**（见 §4 幻象触觉）。先做食指+拇指两指原型，验证后再扩到全手。

## 3. 每个小块的“状态”

每块是两个互补的执行器通道，三个参数：

| 状态 | 范围 | 物理实现 | 负责的感觉 |
|---|---|---|---|
| `press` | 0–1 | 微型气囊 / 压电弯曲片 / 微推杆 | 被按住、物体的接触面和形状 |
| `amp` | 0–1 | LRA 或 6–8 mm 压电片 | 纹理、滑动、碰撞冲击 |
| `freq` | 80–300 Hz | 同上（手指对 150–300 Hz 最敏感） | 材质粗细：频率 = 滑动速度 ÷ 纹理空间周期 |

可选第四个通道：热（珀耳帖片，只放指尖 1–2 块），用来区分金属/木头、冰/火。

材质表（`glove/render.py` 的 `MATERIALS`）把“丝绸/毛皮/木头/石头/皮肤”映射到粗糙度、纹理周期、软硬。

## 4. 怎么模拟“抚摸”

三条规则，都已在 `render.py` 里实现：

1. **幻象触觉**：接触点落在两块之间时，按距离把能量分给相邻块（能量守恒，各块幅度 ∝ √权重）。手指会感到一个落在中间的点，移动时是连续滑动而不是一格格跳。测试 `test_phantom_centroid_tracks_contact` 验证激活重心单调跟随接触点。
2. **速度决定纹理**：静止按压 → 只有 `press`，不振动；滑动 → 振动频率 = 速度 / 纹理周期，限制在执行器带宽内。轻抚毛皮和刮石头的区别就来自这里。
3. **接触面随力和软硬变化**：用力或材质软，接触斑更大，更多块参与；幅度做限速（slew）避免振铃和爆音。

## 5. 通信协议（`glove/protocol.py`）

`0xA5 | seq | N | N×(press, amp, freq/2) | CRC8`，76 块约 235 字节/帧，1 kHz 下约 1.9 Mbps，BLE 不够，要用 2.4G 私有协议、USB 或 Wi-Fi UDP；BLE 方案需降到 200 Hz 并只发变化的块。

## 6. 硬件路线（建议分三步）

1. **验证算法（1–2 周）**：食指指腹 12 个 LRA + 一块 ESP32-S3 + DRV2605L/PCA9685 驱动，接 Unity 的一个“摸毛皮”场景，调 §4 的参数。
2. **加压力通道（1–2 个月）**：在指尖加气囊或压电片，验证 `press` 对“被按住”真实感的提升。
3. **全手 + 追踪**：76 块、柔性 PCB（FPC）、手指弯曲传感器/IMU、电池与散热；做手套外壳和尺码。

## 7. 已知风险

- 振动无法复现真实的剪切力和温度，“摸到真实皮肤”只能逼近，不要承诺完全一致。
- 阵列越密，布线、发热、功耗越难；全手 76 通道峰值电流需要实测。
- 手指被执行器占据后，原本的触觉会被遮挡，需要薄而软的封装。
- 参数（`sigma`、`GAIN`、频带）目前是经验值，**没有用真人实测过**。

## 8. 下一步需要你确认

- 目标平台：VR 头显（哪一款）还是桌面游戏？决定延迟预算和通信方式。
- 预算与量产目标：个人原型还是产品？决定执行器选型（LRA vs 压电 vs 气动）。
- 是否需要力反馈（阻止手指穿过物体）？这是另一套外骨骼，成本差一个数量级。
