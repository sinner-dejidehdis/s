# 可行性验证与修订方案

结论先说：**“用很多小块不同状态模拟抚摸”这个方向，能做到“可辨认的近似”，做不到“和真实手指触摸无法区分”。** 单靠“小块振动阵列”也不是最优路径，有更有效的组合（见 §3）。

## 2. 我之前方案里要修正的地方

1. **LRA 不能自由调频**（来自执行器常识，非上面的来源）：LRA 是谐振器，只在约 150–250 Hz 的窄带内有效，幅度和频率耦合。README 里“freq 80–300 Hz 独立可调”对 LRA 不成立。要做纹理频率必须用**宽带执行器**（音圈/Voice Coil、压电片），驱动用音频级功放，不是 DRV2605 这类开关式驱动。
2. **12 个/指腹的振动阵列大概率没有意义**：振动会在手指组织里扩散，很难把 6 mm 间距的振动分开感知；商业产品每个指尖只放 1–2 个也印证了这点。这条是我的推断，**需要用 §4 的实验 E1 证实或推翻**。
3. **“能量守恒”的幻象公式和阵列间距没有实测依据**（`render.py` 的 `sigma`、`GAIN`），只是合理起点。
4. **抚摸的核心是剪切力**，不是振动。慢速轻抚时皮肤被横向拉伸，只用振动会像“嗡嗡声”而不是“被摸”。

## 3. 推荐方案：分层，按验证结果决定要不要往下

**Tier A（可行，数周，个人可做）——“指尖单点高质量” + 软件纹理**
- 每个指尖：1 个宽带音圈/压电执行器，渲染**波形**（不只是频率）：用游戏材质的数据驱动纹理合成，更新率 ≥ 1 kHz。
- 手掌：3–4 个 LRA 做碰撞/抓握提示（手掌空间分辨力低，14 mm 间距足够）。
- 硬件：ESP32-S3 + 音频功放（如 I2S + 功放芯片）；Unity 里发接触事件。
- 预期：能区分材质（丝绸/石头）、碰撞、滑动速度；**不能**表现方向感很强的抚摸。

**Tier B（可行，1–3 个月）——加“剪切”表现抚摸方向**
- 在食指/拇指指尖加一个 2 自由度小型剪切模块（参考 HapTip / Haptigami 的思路，位移 ±1–2 mm），渲染接触点在指腹上的切向移动。
- 预期：抚摸方向、摩擦感明显提升（文献支持，但**需要你自己的测试确认收益值得增加的重量和成本**）。

**Tier C（可行但昂贵、笨重）——真正的“很多小块”**
- 气动/微流体阵列（HaptX 路线）：有压力状态，但需要气泵、阀门，成本和重量是产品级的。个人/小团队不建议自研，除非目标就是研发这个技术。

**不可行（目前）**：薄、轻、便宜、全手、同时有压力+剪切+温度且与真实触摸无法区分。

**我的建议**：先做 Tier A，用 §4 的实验判断阵列是否有价值，再决定是否做 Tier B。**不要一上来做 76 块。**

## 4. 验证实验（做完再决定方向，每个都有预设通过线）

| 实验 | 做法 | 通过线 |
|---|---|---|
| E1 局部化 | 指腹上贴 3×4 个小执行器（或每指 4 个），随机单点振动，被试盲指认 | 正确率 > 70%，否则阵列无意义，退回 Tier A |
| E2 幻象连续性 | 两个相邻执行器做幻象移动 vs 序贯开关，被试报告“连续滑动”还是“跳格子” | 幻象组“连续”评分显著更高（≥ 8 名被试） |
| E3 剪切收益 | 同一抚摸：A 仅振动 / B 振动+剪切，被试评“像被抚摸”(1–7 分) 和方向判断 | B 平均分高 ≥ 1.5 分，方向正确率 > 80%，才做 Tier B |
| E4 延迟 | 示波器测“碰撞事件 → 执行器动作” | < 20 ms 端到端 |
