# FRC Scouting（2026 REBUILT）

队员在看台上记录比赛用的网页应用。它是纯静态网页，没有后端：第一次联网打开后就能离线使用，数据靠二维码汇总到负责人的设备。

参考了哪些队伍、借鉴了什么，见 [docs/参考总结.md](docs/参考总结.md)。

## 功能

| 页面 | 谁用 | 做什么 |
|---|---|---|
| 比赛 | 客观记录员（每台机器人 1 人） | 记录起始位置和预装；用区域按钮跟踪机器人在哪；按住大按钮给射球计时，松开后可估计进了几个；记录 Bump/Trench 跨区、掉球、防守、故障；爬塔记录位置、等级、成败和剩余时间；赛后打分、勾选标签 → 生成二维码 |
| 主观 | 每个联盟 1 人 | 三台机器人的 Auto 贡献 %、往返路线、各类标签（自动预填）、DNP、标记、备注 |
| Pit | Pit 记录员 | 机器参数和两张照片，用颜色显示完成进度 |
| 数据 | 负责人 | 摄像头或扫码枪导入、粘贴或文件导入、查看每场 6 个位置的覆盖情况、导出 JSON/CSV |
| 队伍 / 选人 / 预测 | 策略组 | 队伍总表（可排序）、单队详情和图表、选人分数加权排序、手动选人名单（DNP / 已被选）、比赛预测 |

## 比赛当天怎么用

1. **赛前（有网）**
   - 所有设备都打开一次网站，之后断网也能用。
   - 在「设置」里填名字和赛事代码，例如 `2026cmptx`。
   - 负责人填 TBA Read API Key，点「从 TBA 同步」，拉下队伍和赛程。没网时可以粘贴赛程 CSV。
2. **每场比赛**
   - 记录员选好自己的位置（R1–B3），队号会按赛程自动填好。
   - 场上 AUTO 一亮灯就按「比赛开始」。
   - 赛后把二维码给负责人扫。
3. **负责人**
   - 在「数据」页打开摄像头连续扫码，或者用 USB 扫码枪对着文本框扫。
   - 定时再点一次「从 TBA 同步」，拉到新比分后 Fuel 会自动校准。
4. **选人前**
   - 在「选人」页选一个预设、调整权重，点「按分数生成名单」，然后在会上手动调整顺序。

建议多准备一台备用负责人设备，用「导出 JSON」→「文件导入」互相同步，会自动合并去重。

## 部署

不需要编译，把 `scouting/` 文件夹放到任何静态网站服务上就能用。注意离线缓存和摄像头扫码都要求 https 或 localhost。

- **GitHub Pages**：仓库里已经有 `.github/workflows/scouting-pages.yml`。在仓库的 Settings → Pages → Source 选择 "GitHub Actions"，之后 main 分支上 `scouting/` 有改动就会自动发布。
- **本地试用**：`cd scouting && python3 -m http.server 8000`，然后打开 http://localhost:8000

改了文件之后，要把 `sw.js` 里的 `VERSION` 加 1，记录员的设备才会更新到新版本。

## 换赛季

字段、分值、时段、标签、Pit 项目、选人预设都在 `js/config.js` 里。2027 规则公布后：

- 改 `config.js` 里的这些配置；
- 改 `js/analysis.js` 里读取 TBA 比分的部分（`slimTbaMatch`）；
- 如果玩法变化很大，再改 `js/match.js` 的场地按钮。
